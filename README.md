# Blog CMS — Spring Boot Backend

A RESTful content management system for blogging, built with Spring Boot, PostgreSQL, and JWT authentication. Supports role-based access (SUBSCRIBER / AUTHOR / ADMIN), post management, categories, tags, and file uploads.

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Framework | Spring Boot 4.0.1 |
| Language | Java 21 |
| Database | PostgreSQL |
| Migrations | Flyway |
| Auth | JWT (access + refresh tokens) |
| ORM | JPA / Hibernate |
| Build | Maven |

---

## Prerequisites

- Java 21+
- PostgreSQL 14+
- Maven 3.9+

---

## Setup

**1. Create the database**

```sql
CREATE DATABASE "blog-cms";
```

**2. Configure credentials**

Edit `src/main/resources/application.properties`:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/blog-cms
spring.datasource.username=<your_pg_user>
spring.datasource.password=<your_pg_password>
```

**3. Run the application**

```bash
mvn spring-boot:run
```

Flyway will automatically create all tables (V1–V5 migrations) on first startup.

The server starts on **http://localhost:8082**.

## Seeding the Database

The project ships with a data seeder that populates realistic development data. It is **off by default** and safe to run repeatedly (idempotent — skips if data already exists).

### Activate the seeder

**Option A — dev profile (recommended)**

```bash
mvn spring-boot:run -Dspring-boot.run.profiles=dev
```

Or in IntelliJ IDEA: Edit Run Configuration → Active profiles → `dev`

**Option B — single property flag**

```bash
mvn spring-boot:run -Dspring-boot.run.arguments="--app.seed.enabled=true"
```

### What gets seeded

| Entity | Default count | Details |
|--------|--------------|---------|
| Users | 9 | 1 ADMIN + 3 AUTHORS + 5 SUBSCRIBERS |
| Categories | 10 | Technology, Web Dev, DevOps, Security, etc. |
| Tags | 20 | Java, Docker, React, AWS, etc. — generated by Datafaker |
| Posts | ~100 | 25 per eligible author, ~60% PUBLISHED, realistic content |

### Configure the counts

Override any of these in `application-dev.properties` (or pass as program arguments):

```properties
app.seed.authors=5
app.seed.subscribers=10
app.seed.categories=10
app.seed.tags=30
app.seed.posts-per-author=50
```

Post titles, content (multi-paragraph markdown), excerpts, and bios are all generated by **Datafaker** — every seed run produces realistic, varied text at real-world content length.

## API Overview

Base URL: `http://localhost:8082/api/v1`

### Authentication

| Method | Endpoint | Auth | Description |
|--------|----------|------|-------------|
| POST | `/auth/register` | Public | Register a new user |
| POST | `/auth/login` | Public | Login and receive tokens |
| POST | `/auth/refresh` | Public | Refresh access token |

### Posts

| Method | Endpoint | Auth | Description |
|--------|----------|------|-------------|
| GET | `/posts` | Public | List published posts (paginated) |
| GET | `/posts/{id}` | Public | Get a single post |
| GET | `/posts/slug/{slug}` | Public | Get post by slug |
| POST | `/posts` | AUTHOR / ADMIN | Create a post |
| PUT | `/posts/{id}` | AUTHOR / ADMIN | Update a post |
| DELETE | `/posts/{id}` | AUTHOR / ADMIN | Delete a post |
| POST | `/posts/{id}/publish` | AUTHOR / ADMIN | Publish a draft |

### Categories

| Method | Endpoint | Auth | Description |
|--------|----------|------|-------------|
| GET | `/categories` | Public | List all categories |
| GET | `/categories/{id}` | Public | Get a category |
| POST | `/categories` | ADMIN | Create a category |
| PUT | `/categories/{id}` | ADMIN | Update a category |
| DELETE | `/categories/{id}` | ADMIN | Delete a category |

### Tags

| Method | Endpoint | Auth | Description |
|--------|----------|------|-------------|
| GET | `/tags` | Public | List all tags |
| GET | `/tags/{id}` | Public | Get a tag |
| POST | `/tags` | AUTHOR / ADMIN | Create a tag |

## Authentication

**1. Login to get a token**

```bash
curl -X POST http://localhost:8082/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@blog.com","password":"Password123!"}'
```

Response:
```json
{
  "accessToken": "eyJ...",
  "refreshToken": "eyJ...",
  "tokenType": "Bearer"
}
```

**2. Use the token on protected endpoints**

```bash
curl http://localhost:8082/api/v1/posts \
  -H "Authorization: Bearer eyJ..."
```

## Claude Code Agents

This project ships with two local Claude Code agents. Both live in `.claude/agents/` and are only active for this project.

### Tester Agent

Runs the Maven test suite and performs a static code review against the project's Spring Boot conventions (N+1 risks, missing `@Transactional`, hardcoded secrets, soft-delete consistency, etc.).

**How to invoke:**

Ask Claude directly in the chat:

```
run the tester agent
```

Or open the **Agents panel** in the Claude Code UI, select `tester`, and start a conversation.

**What it checks:**

| Check | Description |
|-------|-------------|
| Compilation | `./mvnw compile` must pass |
| Test suite | All JUnit tests must pass |
| Architecture | Controllers must not inject repositories |
| Transactions | Write service methods must have `@Transactional` |
| N+1 queries | List repository methods must use `@EntityGraph` |
| Password security | BCrypt strength 12, no plain-text passwords |
| JWT secret | Must be env-var backed, not hardcoded |
| Response types | Controllers must return DTOs, not entities |
| Bean Validation | Request DTOs must have validation annotations |
| Soft deletes | Queries must filter `isDeleted = false` |
| Logging | No `System.out.println` in source code |
| Flyway | Migration files must be sequential and correctly named |
| Security config | CSRF off, stateless sessions, JWT filter order |

---

### Coder Agent

Implements features following the project's established patterns. Use this when building anything new — it reads the existing code first, plans the approach, implements across all layers (entity → repository → service → controller → DTO → migration), compiles to verify, commits, and then writes the dev-doc automatically.

**How to invoke:**

```
run the coder agent — add a <feature> endpoint
```

Or open the **Agents panel** in the Claude Code UI and select `coder`.

**What it does automatically:**

1. Reads `CLAUDE.md` and the relevant existing files before writing anything
2. States its plan (files to create/modify, patterns to follow, decisions to make) before coding
3. Follows all project conventions: layered architecture, Lombok entities, `@EntityGraph`, `@Transactional`, Bean Validation, `@PreAuthorize`, Flyway migrations
4. Runs `./mvnw compile` and fixes errors before committing
5. Commits with a typed message (`feat:`, `fix:`, etc.)
6. Writes a `docs/dev-docs/commit-<N>-<description>.md` teaching doc explaining every decision

---

### Documentation Agent (built into main agent)

The main Claude Code agent (`CLAUDE.md`) has a built-in rule: **after every `git commit`, it automatically generates a dev-doc file in `./docs/dev-docs/`** explaining what was built, why, and what concepts were introduced. This is the teaching log for the project.

The docs follow the naming convention `commit-<number>-<description>.md`. See `docs/dev-docs/` for existing examples.

No manual invocation needed — this runs automatically after every commit Claude makes.

## Developer Notes

- **Postman collection** is available in the repo (`docs/` folder) for quick API testing.
- `spring.jpa.show-sql=true` is enabled by default — all SQL is logged to console.
- JWT secret defaults to a dev key; set `JWT_SECRET` env var in production.
- File uploads go to `./uploads/` by default (configurable via `file.upload-dir`).
