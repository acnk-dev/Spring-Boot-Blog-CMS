# Commit 49 — AIService: Outline & Post Generation

## Overview

This commit introduces the core AI content generation layer of the blog CMS. We create the
`AIService` interface and its implementation `AIServiceImpl`, which use the configured
`ChatClient` (Gemini via OpenAI-compatible endpoint) together with the `PromptTemplateService`
(commit 48) to generate blog post outlines and full Markdown posts from a topic and category.

Four DTOs are added in a new `dto/ai/` package to carry requests and responses cleanly.
The tutorial is extended with Parts 8–10 covering the service architecture, ChatClient fluent
API, outline parsing, and post generation flow.

---

## Problem / Motivation

The `ChatClient` bean and `PromptTemplateService` from the previous two commits are
infrastructure — they do not yet produce anything a user can call. This commit connects
them into real business operations:

1. **Outline generation** — given a topic and category, ask Gemini to produce a structured
   list of section headings the author can review and edit before committing to a full post.
2. **Post generation** — given a topic, category, and the (human-reviewed) outline, ask
   Gemini to write a complete Markdown blog post.

The two-step flow (outline → review → post) is a deliberate UX decision: it inserts a
human checkpoint between a short, cheap AI call and a long, expensive one, and it lets
authors steer the structure before the full content is generated.

---

## Decision

### Why a two-step outline → post flow instead of one-shot post generation?

One-shot generation ("write a full post about Redis") produces structurally inconsistent
output — sometimes 5 sections, sometimes 10, sometimes skipping the introduction. Having
the model generate an outline first and then follow it exactly produces far more predictable
structure and length.

The human review step between the two calls also means the author is not locked into
whatever structure the AI chose. They can add, remove, or reorder sections before the
expensive full-post generation runs.

### Why are `excerpt` and `suggestedTags` stubbed in `GeneratePostResponse`?

`excerpt` and `suggestedTags` require separate AI calls (the excerpt is generated by a
summariser persona; tags by a categorisation expert). Those methods (`generateExcerpt`,
`suggestTags`) are added to `AIService` in commit 50. The fields are present in the DTO
now so the response shape does not change between commits — a client integrated against
commit 49 will work unchanged after commit 50 adds real values.

### Why `dto/ai/` as a separate package instead of `dto/request/` and `dto/response/`?

All AI DTOs are scoped to the AI feature set and have no relationship to post/category/user
CRUD. Grouping them under `dto/ai/` keeps the `dto/request/` and `dto/response/` packages
clean and makes it immediately clear that these DTOs belong to a specific subsystem, not
general CRUD.

### Parsing numbered list — regex vs splitting by index

The AI response is a numbered list like:

```
1. Introduction
2. Core Concepts
3. ...
```

We use a stream + regex filter rather than `split` by index because:
- The model occasionally includes preamble lines ("Here is your outline:") that are not
  numbered — the regex filter discards them automatically.
- The regex `^\\d+[.)].+` handles both `1.` and `1)` formats, both of which Gemini produces.
- A simple `split("\n")[i]` approach would break on any extra blank lines or preamble.

### `service/impl/AIServiceImpl.java` (new)

The implementation wires together the three injected dependencies:

```java
@Slf4j @Service @RequiredArgsConstructor
public class AIServiceImpl implements AIService {
    private final ChatClient chatClient;
    private final PromptTemplateService promptTemplateService;
    private final CategoryRepository categoryRepository;
    ...
}
```

**`generateOutline` flow:**

```java
// 1. Load category (throws 404 if not found)
Category category = categoryRepository.findById(request.getCategoryId())
        .orElseThrow(() -> new ResourceNotFoundException("Category not found..."));

// 2. Get category-aware system prompt + task instruction
String systemPrompt = promptTemplateService.getOutlineSystemPrompt(category);

// 3. Build the user message from request fields
String userPrompt = buildOutlineUserPrompt(request);

// 4. Call Gemini
String response = chatClient.prompt()
        .system(systemPrompt)
        .user(userPrompt)
        .call()
        .content();

// 5. Parse the numbered list into a clean List<String>
List<String> outline = parseNumberedList(response);
```

**`generatePost` flow** — identical structure, but the user prompt includes the outline:

```java
private String buildPostUserPrompt(GeneratePostRequest request) {
    StringBuilder prompt = new StringBuilder();
    prompt.append("Write a complete blog post about: ").append(request.getTopic());
    prompt.append("\n\nFollow this outline:\n");

    for (int i = 0; i < request.getOutline().size(); i++) {
        prompt.append(i + 1).append(". ").append(request.getOutline().get(i)).append("\n");
    }
    // ...
    return prompt.toString();
}
```

**Title extraction:**

```java
private String extractTitle(String content) {
    return Arrays.stream(content.split("\n"))
            .filter(line -> line.startsWith("# "))
            .findFirst()
            .map(line -> line.substring(2).trim())
            .orElse("Untitled Post");
}
```

The system prompt instructs Gemini to include an H1 heading. `substring(2)` strips `# `
(the hash and the space). Falls back to `"Untitled Post"` if Gemini omits the heading.

**Numbered list parser:**

```java
private List<String> parseNumberedList(String response) {
    return Arrays.stream(response.split("\n"))
            .map(String::trim)
            .filter(line -> !line.isEmpty())
            .filter(line -> line.matches("^\\d+[.)].+"))
            .map(line -> line.replaceFirst("^\\d+[.)]\\s*", ""))
            .toList();
}
```

Handles both `1.` and `1)` formats. Discards blank lines and any preamble the model adds
before the list. Returns an empty list rather than throwing if the model returns unexpected
format.

## Concepts Introduced

### ChatClient fluent API — call chain

```java
chatClient.prompt()   // starts a PromptSpec builder
    .system(...)      // sets the system message
    .user(...)        // sets the user message
    .call()           // executes the request synchronously
    .content();       // unwraps the text from ChatResponse → Generation → AssistantMessage
```

`.content()` is a convenience method on `CallResponseSpec` that extracts the string content
from the nested `ChatResponse` object. Equivalent to:

```java
chatClient.prompt()
    .user(...)
    .call()
    .chatResponse()
    .getResult()
    .getOutput()
    .getText();
```

Using `.content()` keeps the calling code clean.

---

### Defensive AI response parsing

AI output is probabilistic — the same prompt can produce slightly different formatting
across calls. Always parse defensively:

- **Filter, don't index**: use `stream().filter()` instead of `response.split("\n")[2]`.
  If the model adds an extra blank line, indexing breaks; filtering does not.
- **Handle missing sections**: use `orElse("fallback")` on `findFirst()` so unexpected
  format produces a usable default, not a NullPointerException.
- **Never trust the format**: even with explicit format instructions, the model may add
  preamble ("Sure! Here is your outline:"). The regex filter in `parseNumberedList` discards
  those lines automatically.

---

### Two-step AI workflows

Many real-world AI features break into a chain of calls where each call produces input for
the next:

```
Step 1: Short, cheap call → structured intermediate result
         (outline generation — a few lines, fast)
               ↓ human review / edit
Step 2: Longer, expensive call using the intermediate result
         (post generation — ~1000 words, slower)
```

This pattern has two advantages:
1. **Cost** — if the user is not happy with the outline, they can refine it before triggering
   the expensive post generation.
2. **Quality** — the model follows an explicit structure better than improvising one. Giving
   it the outline as a constraint produces more consistent posts.
